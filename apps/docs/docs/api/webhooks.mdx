---
title: Webhooks
description: Get crawl, map and batch scrape job events POSTed to your server, signed with your secret.
---

Add `webhook` to a [crawl](/api/crawl), [map](/api/map) or [batch scrape](/api/batch-scrape)
request:

```json
{
  "url": "https://example.com",
  "webhook": {
    "url": "https://hooks.example.net/buncrawl",
    "secret": "a-random-secret-of-16-plus-characters",
    "events": ["state_changed", "page_completed"]
  }
}
```

| Field | Description |
| --- | --- |
| `url` | An `https` URL to POST to. |
| `secret` | 16–256 characters; signs every delivery. |
| `events` | Which [events](/api/jobs#events) to send: `state_changed`, `progress`, `item_completed`, `page_completed`. All of them when left out. |

## Deliveries

Each event is a `POST` with the event's JSON as the body:

```json
{ "jobId": "job_3f2c…", "sequence": 4, "event": "state_changed", "state": "completed", "timestamp": "2026-11-23T10:02:00.000Z" }
```

| Header | Value |
| --- | --- |
| `x-buncrawl-signature` | `sha256=` and the hex HMAC-SHA256 of `<timestamp>.<body>` with your secret |
| `x-buncrawl-timestamp` | The timestamp used in the signature, in milliseconds |
| `x-buncrawl-delivery` | `<jobId>:<sequence>`, unique per event; use it to ignore duplicates |

Answer with any `2xx` status within 10 seconds. Otherwise the delivery is retried, waiting 1, 2,
4 and then 8 seconds, for 5 attempts in all. Redirects aren't followed, and the webhook URL must
resolve to a public address.

## Verifying the signature

```ts
import { createHmac, timingSafeEqual } from "node:crypto";

function verify(body: string, timestamp: string, signature: string, secret: string): boolean {
  const expected = `sha256=${createHmac("sha256", secret).update(`${timestamp}.${body}`).digest("hex")}`;
  return (
    expected.length === signature.length &&
    timingSafeEqual(Buffer.from(expected), Buffer.from(signature))
  );
}
```

Use the raw request body, before parsing it as JSON. Rejecting old timestamps protects against
replayed deliveries.
