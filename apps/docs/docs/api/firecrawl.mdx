---
title: Firecrawl compatibility
description: The /v2 endpoints accept Firecrawl v2 requests, so Firecrawl SDKs and clients work against buncrawl.
---

buncrawl answers Firecrawl's v2 API under `/v2`. Point a Firecrawl SDK at your server's URL and use
your `BUNCRAWL_API_KEY` as the API key.

| Endpoint | Notes |
| --- | --- |
| `POST /v2/scrape` | |
| `POST /v2/crawl`, `GET`/`DELETE /v2/crawl/:id`, `GET /v2/crawl/:id/errors` | `limit` defaults to 10,000 pages, as in Firecrawl. |
| `POST /v2/batch/scrape`, `GET`/`DELETE /v2/batch/scrape/:id`, `GET /v2/batch/scrape/:id/errors` | |
| `POST /v2/map` | Waits for the map to finish; on timeout it returns the links found so far with a `warning`. `limit` defaults to 5,000. |

Other Firecrawl endpoints, such as extract, search and agent, return `404 UNSUPPORTED_ENDPOINT`.

## Differences

- **Formats:** `markdown`, `html`, `rawHtml`, `links`, `screenshot` (with `fullPage` and
  `viewport`) and `branding` work. Others, including `json`, `summary`, `images` and
  `changeTracking`, are rejected; use [`/v1/scrape`](/api/scrape#structured-json) for structured
  JSON.
- **Options:** a Firecrawl option buncrawl doesn't support is rejected with `400
  UNSUPPORTED_OPTION` rather than silently ignored, for example `actions`, `headers`,
  `includeTags`, `includePaths`, `location`, or `ignoreRobotsTxt: true`. A few that don't change
  results, such as `blockAds` and `removeBase64Images`, are accepted and ignored.
- **Webhooks** need `BUNCRAWL_WEBHOOK_SECRET` on the server, because Firecrawl requests carry no
  secret; buncrawl signs deliveries with it. `headers` and `metadata` aren't supported.
- **Errors:** timeouts come back as `408 SCRAPE_TIMEOUT`, as in Firecrawl.
- **Credits:** `creditsUsed` counts succeeded pages.
