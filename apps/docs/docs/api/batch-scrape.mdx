---
title: Batch scrape
description: POST /v1/batch/scrape starts a job that scrapes a list of URLs.
---

```bash
curl -s localhost:3000/v1/batch/scrape \
  -H "Authorization: Bearer $BUNCRAWL_API_KEY" \
  -H "content-type: application/json" \
  -d '{"requests": [{"url": "https://example.com"}, {"url": "https://example.org", "formats": ["html"]}]}'
```

The job runs in the background and returns `202` with a `jobId`. Read the results with
[`GET /v1/batch/scrape/:id`](/api/jobs).

## Request

| Field | Type | Description |
| --- | --- | --- |
| `requests` | array | 1–1,000 [scrape requests](/api/scrape#request), each with its own options. |
| `webhook` | object | [Webhook](/api/webhooks) to notify. |

- Each URL is scraped like [`POST /v1/scrape`](/api/scrape), including the cache, so `maxAge`
  works per request.
- A batch job has 120 seconds in total; each request's `timeout` is capped by that.
- A URL that fails, for example because it's blocked or unreachable, fails only its own item.
- The server accepts at most 10,000 batch items queued or running at once; a batch that would go
  over gets `429 QUEUE_FULL`.
